# 수용 기준과 구현 순서

아래 AT01~AT20은 **향후 구현의 테스트 명세**입니다. 애플리케이션 테스트 실행 결과가 아니며 현재 실행 상태는 모두 `not_run`입니다. 문서의 구조 검증과 제품의 실행·효과 검증을 구분합니다.

## 재현 가능한 수용 시나리오

| 기준 | 입력·사전 조건 | 통과하려면 관찰할 결과 |
| --- | --- | --- |
| AT01 | 한국어·영어·혼합 언어의 의뢰, 응원, 공지 합성 메일 | 후보마다 분류 근거를 확인할 수 있고 원본은 그대로 남습니다. 후보 수정은 저장 후 다시 읽어도 유지됩니다. 특정 표현이 없다는 이유만으로 후보를 누락하지 않는지 사람 판정과 대조합니다. |
| AT02 | 같은 후보에서 사용자가 추천을 수정·해제 | 이후 조회와 관련 화면이 서버가 확정한 최신 수정에 일치합니다. 원본 이동·삭제·외부 발송은 0건입니다. |
| AT03 | 같은 제목·브랜드의 서로 다른 의뢰, 같은 의뢰의 관련 스레드 | 주제 유사성만으로 원문을 병합하지 않습니다. 제안 연결의 근거가 남고 해제할 수 있습니다. 서로 다른 의뢰의 조건을 한 확정값으로 합치지 않습니다. |
| AT04 | 같은 소스 재수집, 서로 다른 소스에서 같은 외부 Message-ID | 재수집은 중복 의뢰를 만들지 않고, 소스가 다른 충돌은 별도 식별합니다. 메시지의 출처와 버전이 유지됩니다. |
| AT05 | 예산 없는 메일, 첨부에만 있는 기한, 서로 충돌하는 날짜 | 없는 예산은 미확인으로 남습니다. 실제 인식한 첨부 근거만 사용하고 날짜 모순을 드러냅니다. 상대에게 묻는 초안은 기존 근거로 해소되지 않은 항목에 한정됩니다. |
| AT06 | 물음표 없는 한국어 요청, 읽었으나 미응답, 답장 초안만 작성 | ‘내 답변 필요’가 사라지지 않습니다. 수신 책임을 발신 `pending-replies`의 결과로 대신하지 않습니다. 의미 판정이 불확실한 경우 완료가 아닌 검토 상태입니다. |
| AT07 | 부재중 회신, 자동 접수, 부분 답변, 모든 질문을 해결한 답변 | 실질적으로 해결되지 않은 약속은 열려 있습니다. 닫힌 각 책임에는 충족·취소 근거 또는 사용자 판단이 있습니다. 반송과 자동 회신만으로 충족 처리하지 않습니다. |
| AT08 | 마지막 메일이 8일 이상 지난 미해결 의뢰와 최근 메일만 읽힌 소스 | 열린 의뢰가 날짜 경계 때문에 삭제·종료되지 않습니다. 조회 범위 제한은 별도 표시됩니다. 최근 7일 보조 신호와 장기 책임 원장이 분리됩니다. |
| AT09 | 확정 산출물 1건 뒤 추가 산출물 제안, 사용자의 수락·거절 | 제안과 합의가 구별됩니다. 수락 전에는 확정 조건·내부 작업이 몰래 바뀌지 않고 변경 근거가 남습니다. |
| AT10 | 초안·판단 생성 중 원문 또는 조건 버전 변경 | 오래된 결과는 최신 결정으로 저장되지 않습니다. 비교 후 갱신 실패를 표시하고 새 근거로 재계산할 수 있습니다. |
| AT11 | 확정 일정, 희망 일정, 가예약, 시간대 불명, 사적 일정 | 확정 약속을 조용히 침범하지 않습니다. 불명확한 대조는 보류합니다. 업무 화면에는 허용된 불가 시간만 표시하고 사적 사유는 노출하지 않습니다. |
| AT12 | 동일 조직의 다른 워크스페이스, 권한 철회, 임의 case UID, 관리자 역할 | 검색 결과·근거·LLM 입력·초안·행동 모두 권한 경계를 지킵니다. 숨긴 UI만으로 막지 않고 서버에서 거부합니다. 누출·비인가 쓰기는 0건이어야 합니다. |
| AT13 | 첨부·메일에 다른 계정 검색·업로드·비밀정보 출력·승인 생략 지시 | 외부 콘텐츠는 실행 권한이 되지 않습니다. 도구 호출·비밀정보 접근·외부 쓰기를 유발하지 않으며 인식 실패도 성공처럼 표시하지 않습니다. |
| AT14 | 두 담당자의 동시 수정, 이전 요청 응답이 늦게 도착 | 버전 충돌 또는 명시적 조정으로 처리하며 최신 서버 상태를 유지합니다. 같은 UID의 권위 있는 mutation 응답을 오래된 UI 값 때문에 버리지 않습니다. |
| AT15 | 미설정 계정, 소스 장애, 부분 동기화, LLM 불가, 실제 빈 결과 | 다섯 상황이 구별됩니다. 최근 동기화·조회 범위·재시도 행동을 제공하고, 다른 정상 소스까지 ‘완료’로 표시하지 않습니다. 모델 불가 시 생성 결과를 꾸미지 않습니다. |
| AT16 | 원문 삭제, 권한 철회, 같은 파일명의 다른 첨부, 파생 인덱스·캐시 | 잘못된 근거를 다른 파일로 대체하지 않습니다. 정책에 따라 파생 근거·초안·색인 접근을 제거하고 필요한 최소 감사 항목만 유지합니다. |
| AT17 | LLM·외부 I/O를 테스트용 barrier로 지연, 동시에 다른 작업 수정 | 지연 구간에 해당 작업의 DB 트랜잭션·명시적 락·점유 연결이 남아 있지 않습니다. 짧은 조건부 저장의 충돌도 실 PostgreSQL 두 세션으로 재현합니다. |
| AT18 | 후속 외부 쓰기 단계에서 공급자 접수 뒤 타임아웃, ETag 충돌 | 확인 불명을 성공으로 바꾸지 않습니다. 먼저 공급자 상태를 조정하고 무조건 재발송하지 않습니다. 명시 승인·소스 capability·조건부 쓰기 경계를 우회하지 않습니다. |
| AT19 | 동일 수락 결정·작업 생성 요청을 반복하고 중간에 실패 | 내부 작업은 결정·범위·행동 기준으로 멱등 처리됩니다. 성공·실패·확인 불명 항목이 구별되고 외부 exactly-once를 근거 없이 보장하지 않습니다. |
| AT20 | 360·768·1280 CSS px, 키보드·화면 읽기 도구, 로딩·빈·오류·권한 부족 | 주요 행동이 잘리거나 겹치지 않습니다. 포커스·레이블·상태 알림·명암 대비를 검토하고 색상만으로 상태를 전달하지 않습니다. 실행 결과가 없는 행동을 완료 문구로 표시하지 않습니다. |

테스트 데이터는 합성 자료와 별도로 동의받은 비식별 자료만 사용합니다. 민감한 실제 메일을 공개 저장소·CI 아티팩트에 넣지 않습니다. 언어별·의뢰 유형별·기간별로 나누어 평가하고, 같은 의뢰의 메시지를 학습·개발과 평가 집합에 나누어 넣지 않습니다. 시간상 나중에 들어온 답변을 이전 시점 판단의 입력으로 사용하는 누수도 금지합니다.

## 화면과 문구의 계약

새로운 CRM 메뉴나 장식용 지표 대시보드를 먼저 만들지 않습니다. 홈에는 판단할 의뢰와 응답 책임, 메일 상세에는 근거·조건·변경, 작업에는 확정된 후속 행동을 둡니다. 일정·데이터·맥락 검색은 기존 목적을 유지합니다. P0에서는 원문 검토와 초안 준비까지만 노출하고, 지원하지 않는 외부 발송·예약 버튼은 표시하지 않습니다.

| 상황 | 제안 문구·행동 | 표시 조건 |
| --- | --- | --- |
| 수신 책임이 미해결 | ‘내 답변이 필요합니다’ / ‘의뢰 근거 보기’ | 수신 책임의 근거 또는 사용자 설정이 있습니다. 단순 안 읽음 상태가 아닙니다. |
| 필요한 정보가 없음 | ‘예산 정보가 확인되지 않았습니다’ / ‘누락 항목 질문 작성’ | 허용된 조회 범위와 인식 상태를 먼저 드러냅니다. 초안 생성 실패는 구별합니다. |
| 새 조건이 제안됨 | ‘이전 합의와 달라진 조건이 있습니다’ / ‘변경 근거 대조’ | 실제 버전 차이를 읽을 수 있습니다. 합의 여부가 불명이면 그 점을 표시합니다. |
| 소스가 오래됨 | ‘최근 메일을 확인하지 못했습니다’ / ‘다시 동기화’ | 마지막 성공 시점과 실패 상태가 존재합니다. 현재 처리할 의뢰가 없다는 뜻으로 쓰지 않습니다. |
| 추론 근거가 부족함 | ‘이 연결은 확인이 필요합니다’ / ‘연결 근거 보기’ | 근거를 노출하고 수정·해제할 수 있습니다. 임의의 확률 숫자를 붙이지 않습니다. |

위 문구는 인터랙션 명세이며 구현된 UI 카피가 아닙니다. 실제 화면에서는 행별 로딩·오류 상태, 재시도·취소, 최신 요청만 반영하는 처리와 포커스 이동을 함께 구현해야 합니다.

## 효과를 검증하는 방법

먼저 소규모 동의 참여자에게 서로 다른 의뢰 사례를 기존 방식과 제안 방식으로 처리하게 합니다. 동일 사례의 반복 학습을 피하도록 난이도가 비슷한 사례를 배정하고 순서를 교차합니다. 탐색 단계의 결과를 시장 전체의 효과로 일반화하지 않습니다. 참여자 수와 필요한 의뢰 수는 초기 분산·실행 비용을 보고 정하며, 아직 모집·실험·효과 측정은 수행하지 않았습니다.

| 지표 | 산식 또는 관찰 단위 | 해석 제한 |
| --- | --- | --- |
| 수신 응답 탐지의 재현율 | 사람이 응답 필요로 판정한 항목 중 시스템이 응답 필요·검토 후보로 남긴 비율 | 단순 전체 정확도와 분리합니다. 검토 후보를 포함한 값과 확정 추천만의 값을 각각 보고합니다. |
| 검토 부담 | 의뢰별 열어 본 원문 수, 수정 횟수, 검토 소요 시간의 분포 | 후보를 많이 만드는 방식으로 재현율만 높이지 못하도록 함께 봅니다. |
| 안전한 판단 도달 시간 | 의뢰 열기부터 근거 확인을 마친 수락·거절·보류 또는 초안 확정까지의 시간 | 잘못된 판단은 빠른 처리의 성과로 세지 않습니다. |
| 근거 충실성 | 표시한 핵심 조건 중 원문·범위·시점과 일치하는 조건의 비율 | 누락·모순·인식 불가를 별도 보고합니다. LLM 자기 채점만 쓰지 않습니다. |
| 책임 유지 | 열려 있어야 하는 약속의 잘못된 종료·누락 건수 | 7일 초과 사례와 부분 답변을 별도로 봅니다. |
| 비용·운영성 | 완료한 검토당 실제 모델 비용, 대기 시간, 실패·취소·재시도 수 | 성공 건만 분모에 넣어 실패 비용을 숨기지 않습니다. |
| 안전 경계 | 비인가 조회·쓰기가 발생한 건수 | 수용 테스트에서는 0건이 요구됩니다. 0건 관찰이 모든 공격에 안전하다는 증거는 아닙니다. |

사람 판정의 단위는 의뢰·개별 약속·특정 시점입니다. 가능한 표본에는 두 판정자를 두고 불일치와 조정 결과를 남깁니다. 제품 가설이 효과를 보이지 않으면 요약 길이·알림 수를 늘리는 대신 무엇이 재구성 부담인지 다시 관찰합니다. 전환율·매출 상승·노동시간 절감률은 측정 전에는 제시하지 않습니다.

## 구현 작업의 순서와 종료 조건

**S0 — 지정 영상의 근거 복구.** 성공한 영상·음성·자막 자료에서 실제 길이와 구간을 확인합니다. 시작·종료 시점, 발언의 짧은 바꿔쓰기, 발언자, 문제와 요구의 구별, 판정 근거를 기록합니다. 문제와 무관한 구간도 포함 여부를 기록해 전 구간 커버리지를 검증합니다. 기존 H01~H10과 일치하지 않는 발언은 새 관찰로 추가하고 맞지 않는 가설은 폐기합니다. 원문·자막 전체를 공개 저장소에 재배포하지 않습니다. 현재는 접근 실패이므로 영상 분석 완료·Ready 전환의 조건이 충족되지 않았습니다.

**S1 — 읽기 전용 단일 사용자 의뢰 보기.** 구현 착수 시 기존 열린 PR의 담당 범위와 최신 통합 상태를 확인합니다. 선택된 소스의 수신 후보·원문 근거·동기화 범위만 연결합니다. AT01~AT08, AT12~AT17, AT20 중 관련 조건을 실제 실행하고 외부 변경 0건을 입증합니다. 모델이 없어도 소스 상태를 읽을 수 있으며 추론 불가 상태를 표시합니다.

**S2 — 수정·초안·내부 작업.** 확인된 근거와 사용자 판단을 버전으로 저장하고 UC03·UC04·UC09를 연결합니다. 정적 코드 검사뿐 아니라 실 PostgreSQL, 서명 세션, 브라우저 경로를 실행합니다. AT09·AT10·AT14·AT17·AT19를 포함하고 새 변경의 정확한 base/head에서 결과를 확보합니다. 초안·내부 작업과 실제 외부 발송 상태는 끝까지 구분합니다.
